# STAT 214 Lab 1 — PECARN / TBI EDA + Modeling Pipeline

This repository contains a fully reproducible pipeline to:

1) read the raw dataset from `data/`  
2) clean the data (`code/clean.py`)  
3) train/evaluate models (`code/models.py`)  
4) generate figures (`code/figures.py`)  
5) (optional) render the report notebook to PDF via Quarto (`report/lab1.ipynb → report/lab1.pdf`)

---

## Project structure

```
lab1/
  code/
    run.sh
    clean.py
    models.py
    figures.py
    environment.yaml
  data/
    <raw dataset>.csv
    cleaned_data.csv            (generated)
  model_output/                 (generated)
  figs/                         (generated)
  report/
    lab1.ipynb
    lab1.pdf                    (optional, generated by Quarto)
```

## Requirements

### 1) Conda (recommended)
You should have **conda** installed (Anaconda or Miniconda).

### 2) Quarto (optional, for PDF)
If you want to render `report/lab1.ipynb` into a PDF, you must install **Quarto** separately.

## Quick start

### Step 1 — Put the raw CSV in `data/`
Put your original dataset CSV file into:

```
lab1/data/
```

It can be named anything, as long as it’s a `.csv`.  
The script will automatically pick the first CSV it finds in `data/` (excluding `cleaned_data.csv`).

### Step 2 — Run the pipeline
From anywhere:

```bash
bash lab1/code/run.sh
```

What you should see:
- A conda environment is created/updated from `code/environment.yaml`
- `cleaned_data.csv` is generated
- model artifacts are written to `model_output/`
- figures are written to `figs/`
- conda environment is deactivated at the end

---

## What `run.sh` does (high level)

`code/run.sh` executes the pipeline in this order:

1. **Conda environment**
   - Ensures the env `stat214` matches `code/environment.yaml`
   - Activates the env

2. **Clean**
   - Reads raw CSV from `data/`
   - Writes `data/cleaned_data.csv`

3. **Model**
   - Reads `data/cleaned_data.csv`
   - Writes model outputs to `model_output/`

4. **Figures**
   - Copies required model artifacts into `figs/` (because `figures.py` expects them there)
   - Generates figures into `figs/`

5. **(Optional) Report**
   - The Quarto render section is currently commented out in `run.sh`
   - If you want PDF rendering, see “Rendering the report to PDF” below.

6. **Deactivate conda**
   - Always deactivates at the end

## Cleaning: how `clean_data()` is called

In `run.sh`, cleaning is done by importing `clean_data()` from `code/clean.py` and calling:

```python
df_clean = clean_data(
    raw_csv,
    drop={"02": True},
    set_na={"07": True, "08": True},
)
```

### What `drop={...}` means
`drop` is a dictionary of **row-dropping rules** (hard filters).

- Keys like `"02"` are **step IDs** defined inside `clean.py`
- Value `True` means: apply that step, and **drop rows** that fail that rule
- Value `False` means: skip that drop step

So:

- `drop={"02": True}` means: enable cleaning step **02**, and for step 02, rows that violate the rule will be removed.

### What `set_na={...}` means
`set_na` is a dictionary of **cell-fixing rules** (soft fixes).

- Keys like `"07"` / `"08"` are **step IDs** defined inside `clean.py`
- Value `True` means: apply that step, and **set specific fields to NA** when a contradiction is detected
- Value `False` means: skip that NA-fix step

So:

- `set_na={"07": True, "08": True}` means: enable steps **07** and **08** and repair contradictions by setting certain conflicting detail fields to missing values (NA), *without dropping the entire row*.

### Where to see the exact logic of steps “02 / 07 / 08”
The step IDs are implemented inside `code/clean.py`.  
Open `clean.py` and search for `"02"`, `"07"`, `"08"` (or the step labels in comments). That file is the source of truth for:
- what condition is checked,
- whether rows are dropped (`drop`) or only some columns are set to NA (`set_na`),
- which variables are modified.

## Outputs

### Cleaned data
- `data/cleaned_data.csv`

### Model artifacts (written by `models.py`)
- `model_output/model_outputs.npz`  (required for figures)
- plus other artifacts like:
  - `perm_importance.csv`
  - `metrics.json`
  - `confusion_matrices.csv`
  - `stability_metrics.csv`
  - `stability_rates.csv`

### Figures (written by `figures.py`)
- `figs/fig1.png`, `figs/fig2.png`, ...
- `figs/figm1.png` … `figs/figm5.png`
- `figs/figf1.png` … etc.

> Important: `figures.py` expects `model_outputs.npz` inside the **same `out_dir` it is writing to**.  
That’s why `run.sh` copies `model_output/model_outputs.npz` into `figs/` before running `figures.py`.
